# Power Automate フロー作成手順（QA_PoC）

このPoCでは、**Power Automate (PA) が「アイテム作成を検知した事実」だけを記録**します。
回答生成はローカルの `broker.py`（Ollama）が担当します。PAは *検知記録係* に徹します。

本番構成ではこの検知トリガーの先で「カスタムコネクタ→社内OpenAI互換API」を呼びますが、
検証環境ではそれが使えないため、**PAは Status を `Detected` にし、`DetectedAt` に UTC 時刻を書くだけ**にします。

---

## フロー仕様

| 項目 | 値 |
|---|---|
| トリガー | SharePoint「**項目が作成されたとき**」 |
| サイト | このPoCのSPOサイト |
| リスト名 | `QA_PoC` |
| アクション | SharePoint「**項目の更新**」 |

### 「項目の更新」で設定する列（**これ以外は触らない**）

| 列 | 値 |
|---|---|
| Id | トリガーの `ID`（動的コンテンツ） |
| Status | `Detected` |
| DetectedAt | 式 `utcNow()` |

- **Title は必須項目なので、トリガーの `Title` をそのまま渡す**（空更新にしない）。
- Question / Answer / SessionId / Turn などの他列は**空欄のまま**にし、上書きしないこと。

---

## 作成手順（テキスト・スクショなし）

1. https://make.powerautomate.com を開く（PoCサイトと同じテナントのアカウント）。
2. 「+ 作成」→「**自動化したクラウド フロー**」。
3. フロー名を `QA_PoC-detect` 等にし、トリガー検索で **「項目が作成されたとき」(SharePoint)** を選択 →「作成」。
4. トリガーの **サイトのアドレス** に PoC の SPO サイト、**リスト名** に `QA_PoC` を選択。
5. 「+ 新しいステップ」→ SharePoint **「項目の更新」** を追加。
   - サイトのアドレス / リスト名：同上
   - **Id**：動的コンテンツの `ID`
   - **Title**：動的コンテンツの `Title`（必須項目のため必ず入れる）
   - **Status**：`Detected`
   - **DetectedAt**：式エディタで `utcNow()`
6. 保存。テストで手動 or 実アイテム作成で発火を確認。

---

## 本番移行時の注意

- **更新トリガーは併用しない**（本フローは「作成時」のみ）。「項目の更新」で他列を空更新しない設定にしておけば、
  仮に将来更新トリガーを足しても無限ループを避けやすい。
- PA の発火は数秒〜十数秒の遅延があり得る。`latency.csv` の `CreatedAt → PA_DetectedAt` 区間がこの遅延の実測値になる。
- 本番では「項目の更新(Detected)」の代わりに **カスタムコネクタ→社内API→Answer/AnsweredAt 書き戻し** に置き換える。
  その場合 broker は不要になり、UI のポーリングはそのまま流用できる。

---

## PA を使わずに検証したい場合（代替）

PA を作らずに broker → Ollama 経路だけ試すには、作成されたアイテムの **Status を手動で `Detected`** に変えます
（SPO のリスト画面で編集、または `setup/sim-pa` 相当の補助）。broker は `Detected` のものだけを拾うので、
`Pending` のまま放置すれば「PA を止めた状態では回答が返らない」ことも同時に確認できます。
